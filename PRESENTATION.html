The Problem

⏱ The Cost of Manual Search

  • NOC engineers spend 30–90 minutes searching fragmented runbooks during live outages
  • Knowledge is scattered across PDFs, wikis, and tribal memory
  • Every minute of delay compounds business impact
  • Multi-vendor environments (Cisco + Juniper) double the complexity

🌐 Multi-Vendor Complexity

A BGP Idle (Admin) state on IOS-XR requires different remediation than on JunOS — but search tools cannot surface this distinction.

🧠 Cognitive Overload

Engineers simultaneously interpret CLI output, recall protocol state machines, and cross-reference docs — all under time pressure during P1/P2 incidents.

Core question: Can AI reduce time-to-diagnosis from hours to seconds?

RAG Pipeline

📥 Ingestion

  • PDF + Markdown runbooks → text extraction
  • Recursive chunker: 1,000 chars, 200 overlap
  • Metadata per chunk: vendor, protocol, source, tags
  • Stored in ChromaDB with dense embeddings

🔍 Hybrid Retrieval

  • Dense search — vector cosine similarity
  • BM25 sparse search — keyword frequency scoring
  • Reciprocal Rank Fusion — merges both lists
  • Cross-encoder reranker — optional ms-marco-MiniLM

💡 Why Hybrid Retrieval?

Pure vector search misses protocol-specific exact keyword matches. When an engineer's incident is "BGP stuck in Idle (Admin)", BM25 correctly boosts runbook chunks containing the exact phrase "Idle (Admin)" — a state that is semantically adjacent to, but technically distinct from, other BGP idle states. Hybrid retrieval captures both semantic meaning and domain keyword precision.

Priority 1 — Low Confidence

If confidence < 0.6, route to SecondOpinionAgent for a deeper RAG re-query with refined terms. Max 2 iterations.

Priority 2 — BGP Protocol

BGP incidents route to BGPSpecialistAgent, a specialist with deep BGP FSM knowledge and IOS-XR/JunOS BGP command expertise.

Priority 3 — Juniper Device

Juniper-named devices route to JunosSpecialistAgent, trained on JunOS operational mode syntax and adjacency state interpretation.

Every routing decision is persisted in incident.ai_report.orchestration.decisions for full auditability.

Live Test Scenarios

Tested against Cisco DevNet Always-On IOS-XR Sandbox — real device, real CLI output.

✅ Scenario 1 — BGP Admin Shutdown

neighbor 2.2.2.2 shutdown on xrd-1. System output: "BGP neighbor 2.2.2.2 is administratively shut down, preventing session establishment." Correctly distinguished Idle (Admin) from reachability or authentication failure. Confidence: 0.88. Time: 26.2 sec.

✅ Scenario 2 — BGP 0 Prefixes Received

Session established but PfxRcd=0. System identified 3 candidate root causes: inbound route-map filtering, empty peer RIB, route-policy rejection. Correctly diagnosed healthy TCP session with routing/policy issue. Confidence: 0.82. Time: 32.7 sec.

✅ Scenario 3 — False Alarm Detection

Incident titled "OSPF down on xrd-1" — but OSPF was healthy with one full adjacency and 4 routes in the RIB. System output: "OSPF is operationally UP — this is a false alarm. Recommend closing ticket and reviewing monitoring alert thresholds." Confidence: 0.91.

Challenges & How We Fixed Them

⚠ LLM Output Non-Determinism

Problem: Models returned JSON wrapped in Markdown fences, with preamble text, or with missing keys — causing silent downstream failures.

Fix: Three-layer defense — regex fence stripping → json.loads try/except → structured fallback with confidence=0.4, which automatically triggers SecondOpinionAgent.

⚠ Prompt Size Overflow

Problem: IOS-XR CLI outputs (show interfaces, show logging) can be 10,000+ chars. Multi-device context hit LLM context limits.

Fix: _guard_prompt_size() enforces 400,000-char limit; CLI blocks capped at 3,000 chars each.

⚠ bcrypt 5.x / passlib Incompatibility

Problem: 17 integration tests failed with ValueError: password cannot be longer than 72 bytes — passlib 1.7.4 broke with bcrypt 5.0.0's stricter API.

Fix: Replaced passlib's CryptContext with direct bcrypt.hashpw() and bcrypt.checkpw() calls, eliminating the incompatible intermediary.

⚠ Reranker Output Contract Drift

Problem: Reranker fallback path (flashrank not installed) returned chunks without rerank_score key — breaking downstream agent code.

Fix: Both fallback branches now attach rerank_score from the existing vector similarity score, ensuring consistent output schema.

Future Work

📡 Streaming Diagnosis

Server-sent events (SSE) to stream intermediate agent outputs to the NOC dashboard in real time — investigation context first, then analysis, then final report.

🔁 Feedback Loop

Capture engineer acceptance/rejection of AI recommendations to train a preference model — continuously improving diagnosis accuracy through RLHF.

⚡ Automated Remediation

For high-confidence, allow-listed scenarios (e.g., clear ip bgp), execute remediation commands automatically with mandatory human confirmation.

🔗 Multi-Incident Correlation

Group co-occurring alerts by topology adjacency and time window. Diagnose a fiber cut as one causal event rather than dozens of correlated symptoms.

🧠 Domain-Tuned Embeddings

Fine-tune the embedding model on (incident query, runbook passage) pairs from production data to improve retrieval precision on networking terminology.

📊 Causal Graph Reasoning

Model failure propagation causally in the digital twin — reason about upstream physical causes (optical power loss) rather than only protocol-layer symptoms.
